## Approach

- Read existing files before writing. Don't re-read unless changed.
- Thorough in reasoning, concise in output.
- Skip files over 100KB unless required.
- No sycophantic openers or closing fluff.
- No emojis or em-dashes.
- Do not guess APIs, versions, flags, commit SHAs, or package names. Verify by reading code or docs before asserting.
- Reply in the user's language; keep technical terms untranslated.
- Don't restate the prompt before answering.
- Close with the result or decision, not a recap of what's already visible in the diff.
## Skill usage

- Use only the skills relevant to the requested task; do not load the whole catalog.
- An exhaustive or Thermos review is opt-in. Routine implementation uses normal contextual guidance.
- Reviews report findings without editing unless changes are separately requested.
- Project-specific instructions and the user's explicit task determine the scope; these preferences do not expand it.
